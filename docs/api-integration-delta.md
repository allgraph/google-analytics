# Реестр расхождений и карта интеграции

Рабочий документ эпика [GA-21](https://google-analytics.atlassian.net/browse/GA-21).

## Три источника

| Документ | Что это | Статус |
|---|---|---|
| [openapi.yaml](./openapi.yaml) | Согласованный контракт первой очереди | Целевой. Остаётся эталоном по именам и правилам |
| [openapi-backend.yaml](./openapi-backend.yaml) | `AdCallTrack Backend API 1.0.0` — что бэкенд реализовал фактически | Источник для интеграции сегодня |
| `project-materials/prototype/Callgraph — сквозная аналитика.html` | Прототип: согласованный состав экранов и элементов | **Не меняется.** Эталон интерфейса |

## Правило

Экраны и их элементы согласованы и меняться не должны. Если бэкенд не отдаёт данных под элемент,
элемент **остаётся на месте** в согласованном виде, но неактивен и помечен «нет данных» со ссылкой
на backend-задачу. Упрощать интерфейс под возможности API нельзя.

## Замечания к присланному файлу

Найдено при первом прогоне `npx @redocly/cli lint docs/openapi-backend.yaml`.

1. **Спецификация не проходила валидацию — 10 структурных ошибок.** Причина одна: в flow-стиле YAML
   (`{name: …, description: …}`) описания с запятой не заключены в кавычки, и парсер режет строку на
   лишние ключи. Пострадали описания шести тегов и двух полей — часть текста просто терялась.
   Например, `description: Пользователи, роли, проекты и аудит` превращалось в описание
   «Пользователи» плюс два несуществующих свойства.

   При переносе в репозиторий кавычки проставлены; содержание не менялось. Бэкендеру стоит
   поправить у себя в источнике, иначе исправление потеряется при следующей выгрузке.

2. **Ни у одной операции нет `operationId`** — 79 предупреждений. Согласованный контракт
   [openapi.yaml](./openapi.yaml) их содержит. Без `operationId` любая кодогенерация клиента даёт
   имена методов, выведенные из пути, и они меняются при малейшей правке URL. Для нас сейчас не
   блокер (типы ведём вручную), но просьбу стоит передать.

## Расхождения по форме — гасятся адаптером

Задач бэкенду по ним не заводим: форма ответа — его решение, экраны от неё не зависят. Вся разница
живёт в одном месте — адаптере внутри API-клиента (GA-23).

| Аспект | Согласованный контракт | Реализация | Решение |
|---|---|---|---|
| Пагинация | `page` / `per_page` | `limit` / `offset` | Наружу `page`/`per_page`, внутрь перевод в `limit`/`offset` |
| Деньги | строка `"1234.56"` + `currency` | целое в minor units | Перевод в `{amount, currency}`, форматирование в `src/lib/format.ts` |
| Фильтры отчётов | JSON-объект в параметре `filters` | плоские query-параметры | Сборка query в клиенте |
| Типизация ответов | ~100 схем | `data: {additionalProperties: true}` | Типы ведём на фронте сами по схемам из `openapi.yaml`. **Риск:** контракт не проверяется машинно, расхождения ловятся только руками |
| Уведомления | `/notifications`, `/notification-rules` | `/alerts`, `/alert-rules` | Маппинг имён; экран называется «Уведомления» |
| Заявки | `/leads` | `/leads` | Совпадает. Маршрут интерфейса — `/requests` |
| Базовый путь | `/api/v1` | `/api/v1` | Совпадает |

зафиксировано, чтобы не потерялись.

|---|---|
| `POST /auth/bootstrap` | Первичная установка; выполняется один раз вне интерфейса |
| `GET|POST /services`, `/operators`, `/masters` | Справочники. На экранах используются как значения полей, отдельного раздела управления в прототипе нет |
| `POST /webhooks/telephony/{provider}` | Серверная интеграция, фронт не вызывает |

## Как поддерживать документ

1. Реестр заглушек в коде (GA-28) ссылается на ключи из этой таблицы. Источник правды о том, что
   ещё не закрыто, — реестр в коде; этот документ объясняет почему.
2. Backend-задача закрыта → снять заглушку, обновить строку карты с «заглушка» на «есть».
3. Расхождение в именах полей или машинных кодах, найденное при интеграции, — добавлять в раздел
   расхождений по форме, а не править молча в коде.
