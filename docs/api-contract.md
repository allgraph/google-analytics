# Контракт API первой очереди

Авторитетный машиночитаемый контракт находится в [openapi.yaml](./openapi.yaml). Базовый путь всех прикладных ручек — `/api/v1`.

> **Фактическая реализация отличается.** Бэкенд реализовал собственный вариант API — он лежит в
> [openapi-backend.yaml](./openapi-backend.yaml). Этот документ остаётся целевым контрактом и
> эталоном по именам, правилам пагинации и ролевому усечению, но интеграция сегодня ведётся по
> фактической реализации. Построчное соответствие «экран → элемент → ручка → заглушка», реестр
> расхождений и список backend-задач — в [api-integration-delta.md](./api-integration-delta.md)
> (эпик GA-21). Состав экранов и их элементов при этом не меняется.

## Согласованные решения

- Все списки используют `page` и `per_page`; допустимые размеры страницы: `10`, `50`, `100`, `500`.
- Общие фильтры отчётов передаются в query-параметре `filters` как JSON-объект. Все множественные значения внутри него являются массивами.
- ID имеют тип `string`, даты и время — ISO 8601 с явно указанным часовым поясом.
- Денежные суммы передаются строкой с двумя знаками после точки вместе с трёхбуквенным кодом валюты.
- Пустая выборка возвращает `200`, `data: []`, `total: 0`, `from: 0`, `to: 0`.
- Производные показатели с нулевым знаменателем возвращаются как `null`.
- Первый клик по сортируемой колонке отправляет `order=desc`.
- `/requests` — маршрут интерфейса, но соответствующая API-сущность называется `/leads`.

## Ролевое ограничение

Сервер сначала ограничивает область доступных аккаунтов и сайтов, затем удаляет запрещённые поля из ответа. Удалённые поля не должны попадать ни в JSON, ни в экспорт и перечисляются в `meta.hidden_fields`.

| Роль | Область | Скрываемые группы полей |
|---|---|---|
| `owner` | Все данные | Нет |
| `manager` | Назначенные проекты | Нет |
| `marketer` | Назначенные проекты | Деньги |
| `operator` | Звонки и заявки | Деньги |
| `accountant` | Назначенные проекты | Кампания, группа, ключ, объявление |
| `client` | Собственные аккаунты и сайты | Операторы и мастера |
| `technical_admin` | Настройки | Записи и расшифровки разговоров |

Запрос закрытого раздела возвращает `403`. Запрещённые поля также нельзя использовать для сортировки и фильтрации.

## Маршруты интерфейса

| Экран | Маршрут | Основной источник данных |
|---|---|---|
| Дашборд | `/dashboard` | `/dashboard/*` |
| Звонки | `/calls` | `/calls` |
| Карточка звонка | `/calls/:id` | `/calls/{id}` |
| Сопоставление | `/matching?tab=review\|phone-clicks\|unattributed` | `/matching/*`, `/phone-clicks` |
| Заявки | `/requests` | `/leads` |
| Карточка заявки | `/requests/:id` | `/leads/{id}` |
| Аналитика | `/analytics?tab=campaigns\|sites\|missed-calls` | `/analytics/*` |
| Финансы | `/finance` | `/finance/*` |
| Уведомления | `/notifications` | `/notifications`, `/notification-rules` |
| Настройки | `/settings?tab=...` | справочники и `/accounts`, `/sites`, `/users`, `/audit-log` |
| Районы | `/districts` | Заглушка первой очереди; карта и API относятся ко второй |

## Состояния моков

Для каждого списка должны быть доступны четыре сценария:

1. Заполненный `200` — пример из схемы соответствующего ответа.
2. Пустой `200` — пустой массив и нулевая пагинация.
3. `403` — объект `ErrorResponse` с кодом `FORBIDDEN`.
4. `500` — объект `ErrorResponse` с непустым `request_id`.

Дополнительно нужен заполненный ответ с урезанными по роли полями и их перечнем в `meta.hidden_fields`.

## Проверка и мок-сервер

Проверить и запустить контракт можно без изменения frontend-кода:

```bash
npx --yes @redocly/cli lint docs/openapi.yaml
npx --yes @stoplight/prism-cli mock docs/openapi.yaml --port 4010
```

Prism публикует пути спецификации от корня своего локального сервера, поэтому адрес фронтенда для этого мока: `VITE_API_BASE_URL=http://localhost:4010`. Реальный сервер по-прежнему публикует тот же контракт под `/api/v1`.

## Граница первой очереди

Не входят: карта районов, отчётные вкладки «Поисковые запросы», «Услуги», «Операторы», «Мастера», а также редактирование весов и порогов сопоставления. Их маршруты могут существовать как заглушки, но бэкенд первой очереди не обязан реализовывать для них данные.

## Приёмка бэкендом и фронтендом

- OpenAPI проходит lint без ошибок и запускается в Prism.
- Имена полей, фильтров, сортировок и машинные коды словарей не меняются без обновления контракта.
- Повторная отправка `phone_click_id` или `call_id` возвращает существующую запись с `duplicate: true`.
- Все операции возвращают единый `ErrorResponse`; `422` содержит `field_errors`, `429` — `Retry-After`, `500` — `request_id`.
- Переход фронта с Prism на реальный API выполняется только заменой `VITE_API_BASE_URL`.
